# MyMusicLabel
Учебный проект, на котором я тренируюсь моделировать предметную область согласно DDD.

**Статус:** не завершен

**Тесты предметной области:** разрабатываются

## Суть
Приложение для (единственного?) сотрудника небольшого независимого музыкального лейбла, который занимается публикацией музыкальных произведений артистов, с которыми заключен договор, на стриминговых площадках. Позволяет
* публиковать треки на различных площадках и отзывать треки с площадок;
* отмечать заключение и разрыв договоров с музыкальными исполнителями, авторами музыки и текстов
* считать доход, выплаты и прибыль по каждому релизу и в целом за период;
* анализировать динамику количества прослушиваний по релизам;
* учитывать треки, правами на которые владеет лейбл.

Приложение **не предназначено для выполнения никаких платежей (даже имитационных) и не управляет расчетным счетом лейбла**. Приложение исключительно вычисляет, сколько стриминговые платформы должны лейблу, и сколько лейбл должен музыкантам. Поэтому ситуация, когда расходы за период превышают доходы - абсолютно нормальная в рамках данного приложения.

## Архитектура
Решение содержит 3 проекта:
1. MyMusicLabel - слой приложения, CLI
2. MyMusicLabel.Domain - слой предметной области
3. MyMusicLabel.Infrastructure - слой инфраструктуры: фейковые реализации репозиториев и клиентов стриминговых сервисов.

Приложение фактически не хранит никаких данных в БД, репозитории сохраняют данные в оперативной памяти, т. к. проект фокусируется на моделировании предметной области.
